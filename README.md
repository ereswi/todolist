# ToDoリスト

今日を、ひとつずつ。ブラウザーに保存する個人用の日本語ToDoアプリです。

**公開URL: https://ereswi.github.io/todolist/**

HTML・CSS・JavaScript（ES Modules）で動作し、アプリの利用にインストールやログインは必要ありません。ビルド工程もありません。

## できること

- **一日のToDo**: 起動時は今日。前日・翌日・日付指定、進捗、昨日以前の期限超過を表示。
- **タスク管理**: 日付なしを含む一覧、登録・編集・削除、5秒間の削除取り消し、完了切り替え。
- **月カレンダー**: 月・年をまたいだ移動、フォルダ内の未完了件数、日付から日別一覧への移動。
- **整理**: 1階層のフォルダ作成・名前変更・削除、編集画面からの所属変更。フォルダ削除時はタスクを未分類へ移します。
- **絞り込みと並び替え**: すべて・未完了・完了、期限順・作成順（新旧）・日本語名順。並び順は保存されます。
- **期限と通知**: 日付のみ／日時指定、10分前・1時間前・前日同時刻・直接指定のリマインド。
- **保存と表示**: 自動保存・復元、保存失敗の表示、破損データの保護、キーボード操作、PC・スマートフォン幅の表示。

追加は右上の「タスクを追加」から。日別画面では選択日、フォルダ選択中はそのフォルダが初期入力されます。日付を空にすると日付なしのタスクになります。時刻だけの登録はできません。日付だけのタスクは翌日から期限超過です。

カレンダーの件数は、選択フォルダ内の**未完了**タスク数です。一覧の完了状態フィルターとは連動しません。

## 通知の使い方と制約

1. 「通知の設定」→「通知を有効にする」でブラウザーの許可を求めます。
2. 「通知をテスト」でOS通知を確認します。表示されない場合はOS側の通知設定も確認してください。
3. タスクに期限日・期限時刻を入力し、未来かつ期限より前のリマインドを設定します。

通知対象は約20秒ごとに確認します。**通知はページを開いて処理が動作している間のみ**です。非表示タブの制限、タブの休止、PCのスリープ、OSの設定などにより遅延・未表示があり得ます。ページを閉じた後に送るWeb Pushはありません。

通知拒否・未対応・送出失敗時は画面内で確認できます。OS通知の有無にかかわらず、お知らせは画面内にも残します。再起動時・ページ復帰時に過ぎていた通知は画面内にまとめ、過去分のOS通知を連続送出しません。完了・削除済みのタスクは新たに通知しません。

通知処理済み状態は保存され、タスク名・フォルダだけの変更ではリセットされません。通知日時を変更すると新しいリマインドになります。完了を戻す／削除を取り消す場合も元の通知状態を維持します。

複数タブのOS通知重複を防ぐため、localStorageの処理済み状態に加えてIndexedDBの一意キーで送出権を取得します。IndexedDBが使えない環境では、OS通知を控えて画面内に記録します。PCの現行Chrome・Edgeを優先対象とします。

## データの保存

タスク・フォルダ・期限・通知状態・並び順・画面内通知は、利用中のブラウザーのlocalStorage（キー: `ereswi.todolist.v1`）に保存されます。通知の重複防止キーだけはIndexedDB（`ereswi.todolist.notification-claims`）に保存します。利用データをGitHubや外部サーバーへ送信する処理はありません。

- ブラウザー・プロファイル・端末・オリジンが異なるとデータも別です。開発URLから公開URLへ自動移行しません。
- サイトデータの削除やプライベートブラウズの終了などで消える可能性があります。同期・バックアップ機能はありません。
- 保存失敗時は入力ダイアログを閉じず、エラーを表示します。入力を控えたうえで保存設定・空き容量を確認し、もう一度保存してください。
- JSON破損・未知のスキーマは無言で初期化しません。エラー中は元の保存データへの書き込みを止めます。修復時にはブラウザーの開発者ツールで元データを退避してから対応してください。
- 同じタスクを別タブで編集した場合、後から保存した編集が優先されます。タスクやフォルダ名はHTMLとして実行しません。

## ローカル起動

Node.js 24で確認しています。配信だけなら依存パッケージのインストールは不要です。

```sh
npm start
```

[http://127.0.0.1:4173/todolist/](http://127.0.0.1:4173/todolist/) を開きます。終了はCtrl+Cです。`index.html`をファイルとして直接開く方法は対象外です。

## 検証

```sh
npm test
npm ci
# 別のターミナルで npm start を実行した状態で:
npm run test:browser
npm run test:notifications
```

ブラウザーテストはインストール済みのChrome・Edgeを使用し、使い捨てのプロファイル内で合成データを作ります。普段のブラウザーデータには触れません。`test:notifications`はウィンドウを開いて実際のテスト通知を送ります。

公開環境を検証する場合（PowerShell）:

```powershell
$env:TEST_URL = 'https://ereswi.github.io/todolist/'
npm run test:browser
npm run test:notifications
Remove-Item Env:TEST_URL
```

## 公開方法

GitHub PagesのGitHub Actions方式を使用します。mainへのpushで基盤テストを実行し、[公開ワークフロー](./.github/workflows/pages.yml)が列挙したHTML・CSS・JS・アイコンだけをPagesへ配信します。アプリ自体のビルドは不要です。設計資料・テスト・開発用サーバー・依存パッケージはPagesの公開物に含めません。

当初のmainルート全体を公開する案から、配信対象を限定できる方式に調整しました。リポジトリ自体は依頼どおりpublicです。

参考: [GitHub公式の静的サイト用ワークフロー](https://github.com/actions/starter-workflows/blob/main/pages/static.yml)、[Web Locks API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `index.html` / `styles.css` / `icon.svg` | 3画面・ダイアログ・レスポンシブ表示 |
| `app.js` | 共通状態、タスク・フォルダ操作、画面連動 |
| `model.js` / `calendar.js` | 入力検証、ソート、通知対象判定、ローカル日付処理 |
| `storage.js` | スキーマ確認、localStorage、Web Locksによる保存の直列化 |
| `reminders.js` / `notification-claims.js` | 通知、画面内履歴、複数タブの送出権取得 |
| `tests/` | 基盤テスト、ブラウザー操作、ネイティブ通知確認 |
| `scripts/serve.mjs` | ローカルHTTPサーバー |

要件の必須機能は実装済みです。検索・一括削除・繰り返し・ドラッグ並び替え・ログイン・共有・端末間同期・閉じた後の通知は今回の対象外です。
